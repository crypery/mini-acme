# mini-acme

> [English version](README.md)

> [China version](README_CN.md)

**mini-acme** - утилита автоматического управления сертификатами ACME (RFC 8555), написанная на чистом C с использованием библиотеки **crypery** (HTTPS Library).

Для удостоверяющего центра Let's Encrypt утилита запрашивает сертификат по протоколу ACME, используя **HTTP-01** метод проверки прав на домен: на 80-м порту раздаётся специальный проверочный файл `/.well-known/acme-challenge/<token>`, который CA-сервер запрашивает по HTTP.

## Описание

При запуске mini-acme:

1. Создаёт (или загружает из кэша) ACME-аккаунт с RSA-2048 ключом.
2. Запрашивает у Let's Encrypt сертификат RSA-2048 для одного или нескольких доменов: первый `-domain` - основной (CN + имя файлов кэша), все домены попадают в расширение SAN.
3. Проходит проверку владения каждым доменом через HTTP-01: поднимает HTTP-сервер на 80-м порту, который отдаёт проверочные файлы (остальные HTTP-запросы перенаправляются на HTTPS).
4. Сохраняет выданный сертификат (полная цепочка: leaf + intermediate) и ключ в каталог кэша и завершается - HTTPS-сервер не запускается.

Ключ аккаунта и выданные сертификаты хранятся в локальном каталоге кэша (по умолчанию `certs/`): `<primary>.pem` (ключ + полная цепочка), `<primary>.crt` (полная цепочка), `<primary>.key` (ключ). Повторный запуск переиспользует кэшированный сертификат, пока он действует более 30 дней **и** его SAN покрывает все запрошенные домены; иначе выпускается новый.

## Особенности проекта

- **Чистый C, без внешних криптографических библиотек** - весь TLS-стек (TLS 1.2/1.3, AES-128-GCM, SHA-256, HMAC-SHA256, HKDF, RSA-2048, ECDH P-256/X25519, X.509) реализован внутри библиотеки crypery.
- **Полный ACME-цикл**: создание аккаунта, многодоменный заказ сертификата, HTTP-01 валидация каждого домена и получение.
- **Многодоменные (SAN) сертификаты**: повторяйте `-domain` до 8 раз (например, apex + `www`) - все имена попадут в один сертификат.
- **Сертификаты с полной цепочкой**: сохраняемые `.crt`/`.pem` содержат leaf и intermediate, поэтому браузеры строят цепочку без ошибок.
- **Кроссплатформенность**: Windows (Winsock2/WinAPI) и POSIX (BSD-сокеты, pthreads) - один и тот же исходный код.
- **Одноразовый запуск**: получает сертификат и завершается - ни демонов, ни открытых портов после выхода.
- **Кэширование**: повторный запуск не создаёт новый аккаунт и не запрашивает новый сертификат, пока кэшированный действует более 30 дней и покрывает все запрошенные домены; устаревший кэш (истекающий или без нужного SAN-имени) вызывает перевыпуск.
- **Минимальные зависимости**: только стандартная библиотека C, pthreads (POSIX) и zlib (gzip-сжатие в HTTP-модуле).
- **Безопасность по умолчанию**: по умолчанию используется staging-контур Let's Encrypt, чтобы не исчерпать лимиты продуктивного CA.

## Используемые модули

| Модуль | Назначение |
|--------|-----------|
| **crypery** | Сетевой стек на чистом C: криптографический слой TLS 1.2/1.3 (`tls`), OpenSSL-совместимый обёрточный слой (`ssl`), HTTP/1.1-сервер (`http`) и HTTP/HTTPS-клиент (`url`). Все криптоалгоритмы реализованы с нуля; используется для ACME-запросов (клиент `url`) и генерации/подписи RSA-ключей (модуль `tls`). |
| **utilery** | Подборка базовых библиотек на C: парсер JSON (`json` - разбор ответов ACME-сервера), модуль логирования (`log`), модуль настроек (`sett`) и библиотека `ecma` (UTF-8 кодек, регулярные выражения, буфер строк). Внешних зависимостей нет. |
| **zlib** | Библиотека сжатия; используется модулем `http` из crypery для gzip-сжатия ответов (опционально, отключается флагом `HTTP_NO_GZIP`). |

## Компиляция

### Windows (build_acme.bat)

Требуется MinGW (gcc в PATH). Запуск:

```bat
build_acme.bat
```

Результат: `mini-acme.exe` в корне проекта.

### Linux (build_acme.sh)

Сборка выполняется в Docker-контейнере с gcc (образ `gcc:13`), поэтому на хосте нужен только Docker. Запуск:

```bash
bash build_acme.sh
```

Результат: бинарник `mini-acme` (ELF, x86-64) копируется в корень проекта.

Образ контейнера можно переопределить переменной окружения `IMAGE` (например, `IMAGE=gcc:14 bash build_acme.sh`).

## Использование

```
mini-acme [-domain <name>]... [-dir <acme-directory-url>] [-cache <dir>] [-email <addr>] [-h]
```

| Аргумент | Описание | По умолчанию |
|----------|----------|--------------|
| `-domain <name>` | Домен для включения в сертификат (повторяемый, до 8; первый = основной: CN + имя файлов кэша, все = SAN) | имя хоста |
| `-dir <url>` | URL ACME-каталога CA | staging Let's Encrypt |
| `-cache <dir>` | Каталог кэша (ключ аккаунта, сертификаты) | `certs` |
| `-email <addr>` | Контактный e-mail для ACME-аккаунта | `admin@example.com` |
| `-h`, `-help` | Справка | - |

### Требования

- Каждый домен должен быть **публично доступен** - его A/AAAA-запись должна указывать на машину, где запущена утилита, иначе HTTP-01 проверка не пройдёт.
- Открытый входящий порт **80** (HTTP-01).
- Права на привязку к порту 80 (на Linux - запуск от root или `CAP_NET_BIND_SERVICE`).

### Примеры

```bash
# Сертификат для example.com в staging-контуре (по умолчанию)
mini-acme -domain example.com

# Apex + www в одном сертификате, продуктивный контур Let's Encrypt
mini-acme -domain example.com -domain www.example.com -dir https://acme-v02.api.letsencrypt.org/directory

# Свой каталог кэша и e-mail
mini-acme -domain example.com -cache /var/lib/mini-acme -email admin@example.com
```

### Пример сессии

```
Domains (2): example.com www.example.com
Obtaining certificate for example.com ...
Certificate valid until: 2026-12-20 12:00:00 UTC
Certificate saved to certs/example.com.pem
Done.
```

Программа завершается после получения сертификата. Чтобы принудительно перевыпустить (например, после добавления домена), удалите файлы кэша основного домена (`certs/<primary>.pem`, `.crt`, `.key`) и запустите снова.
